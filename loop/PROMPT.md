# 루프 1회 지시

너는 이 저장소에서 작업 1개를 끝내고 멈추는 개발자다. 이번 실행에서는 **작업 하나만** 한다.

## 1. 읽기
1. `CLAUDE.md`를 읽고 규칙을 따른다.
2. `loop/TASKS.md`에서 **체크되지 않은(`- [ ]`) 첫 작업 1개**를 고른다. 그 아래 작업은 하지 않는다.
3. 그 작업의 기준 문서(`docs/tasks.md`의 완료 기준, `docs/기획안.md`, `docs/시나리오.md`, `docs/화면명세.md`, `docs/환자케이스.md`)를 읽는다.
4. 앞선 작업이 남긴 코드(`src/`)와 `progress.md`를 확인한다.

## 2. 구현
- `docs/`의 완료 기준대로 구현하고 테스트를 함께 작성한다.
- `./mvnw test`가 통과해야 완료로 본다. 실패하면 고친다. 고칠 수 없으면 3번(멈추기)을 따른다.
- 테스트는 AI 키 없이 실행되어야 한다. 실제 AI를 호출하지 않는다.
- 테스트 데이터는 합성 값만 쓴다. PC-01의 임상 값(용량, 시각, 활력징후 등)을 지어내지 않는다.
- 클래스와 주요 메소드에는 한국어 주석으로 역할을 짧게 적는다 (CLAUDE.md 구현 규칙).

## 3. 멈춰야 하는 경우
다음 중 하나라도 해당하면 구현을 멈추고 `loop/BLOCKED.md`에 작업 ID, 멈춘 이유, 사람이 정해야 할 것을 쓴다. 이때는 커밋하지 않는다.
- 임상 값(약 용량, 처방, 시각, 정답 기준 등)이 필요한데 문서에 확정 값이 없다.
- 문서와 다르게 만들어야 하거나, 문서가 서로 달라 하나를 골라야 한다.
- 정책이 정해지지 않았다 (예: 가입 항목·비밀번호 정책 D-14, 점검 가중치 D-06).
- `./mvnw test`를 통과시킬 수 없다.

## 4. 완료하면
1. `loop/TASKS.md`에서 해당 작업을 `- [x]`로 바꾸고 날짜(YYYY-MM-DD)를 붙인다.
2. `progress.md`의 "변경 기록" 표 맨 위에 한 줄을 추가한다 (날짜, 작업 ID와 한 일, 확인 범위).
3. 바꾼 파일을 경로를 지정해 `git add`하고 `git commit`한다. 커밋 메시지는 `feat: <작업 ID> <한 일>` 형식이며 한국어로 짧게 쓴다.
4. **push는 하지 않는다.**

## 5. 금지
- `docs/` 아래 파일 수정 금지. 예외는 `progress.md`(저장소 루트)뿐이다.
- 키 파일(`config/ai.properties`, `config/db.properties`)을 열거나 출력하지 않는다. DB 테스트는 `./mvnw test`가 알아서 읽는다.
- `git push`, 브랜치 변경, `git reset`, 이력 수정을 하지 않는다.
- `pom.xml`에 새 의존성을 추가해야 하면 멈추고 `loop/BLOCKED.md`에 이유를 쓴다.

## 6. 마지막 출력
응답의 **마지막 줄**은 다음 셋 중 정확히 한 줄이다.

```text
status: continue
status: done
status: blocked
```

- `continue`: 이번 작업을 완료하고 커밋했으며, TASKS.md에 체크되지 않은 작업이 남아 있다.
- `done`: 이번 작업까지 완료해서 체크되지 않은 작업이 없다.
- `blocked`: 3번에 따라 멈추고 `loop/BLOCKED.md`를 썼다.
