# 루프 1회 지시

너는 이 저장소에서 작업 1개를 진행하고 멈추는 개발자다. 이번 실행에서는 **작업 하나만** 한다.
루프는 하루 동안 이어서 돌아간다. 가능한 한 멈추지 말고 다음 회차가 이어받을 수 있게 남긴다.

## 1. 읽기
1. `CLAUDE.md`를 읽고 규칙을 따른다.
2. `loop/TASKS.md`의 공통 기준을 읽고, **체크되지 않은(`- [ ]`) 첫 작업 1개**를 고른다. 그 아래 작업은 하지 않는다.
3. `progress.md`의 변경 기록 맨 위 몇 줄을 읽는다. 이전 회차가 같은 작업에서 테스트 실패 원인을 남겼으면 거기서부터 이어서 고친다.
4. `git status`로 커밋되지 않은 변경이 있으면 이전 회차가 하던 작업이다. 버리지 말고 이어서 한다.
5. 기준 문서를 읽는다: `docs/tasks.md`(완료 기준), `docs/시나리오.md`(**작업과 관련된 S1~S9, V1~V7**), `docs/화면명세.md`, `docs/기획안.md`, `docs/환자케이스.md`, `docs/결정기록.md`(D23~D26).

## 2. 구현
- 관련 시나리오(S1~S9)의 단계와 기대 결과를 기준으로 구현하고, 그 기대 결과를 테스트로 확인한다.
- `docs/tasks.md`의 완료 기준을 만족해야 한다. `./mvnw test`가 통과해야 완료다.
- 테스트는 AI 키 없이 실행되어야 한다. 실제 AI를 호출하지 않고 가짜 응답을 쓴다.
- 테스트 데이터는 합성 값만 쓴다. DEMO 케이스 값은 `docs/환자케이스.md`의 Figma 예시 값에서만 고른다.
- 저장소 코드는 인터페이스 뒤에 두고 단위 테스트는 메모리 구현을 쓴다. MySQL 테스트는 `config/db.properties`가 없으면 건너뛰게 만든다 (`MySqlConnectionTest` 참고).
- 클래스와 주요 메소드에 한국어 주석으로 역할을 짧게 적는다. Swing·JDBC 규칙은 CLAUDE.md '구현 규칙'을 따른다.
- 화면 테스트는 화면을 띄우지 않고 검증 가능한 로직(입력 검증, 상태, 이동 결정)을 테스트한다. CI는 화면이 없는 환경이다.

## 3. 테스트가 실패하면
1. 실패 메시지와 원인을 찾아 고치고 `./mvnw test`를 다시 돌린다. 이번 회차 안에서 여러 번 반복해도 된다.
2. 이번 회차에 끝내 고치지 못하면:
   - TASKS.md는 체크하지 않는다.
   - `progress.md` 변경 기록 맨 위에 `날짜 | <작업 ID> 진행 중 | 테스트 실패: <원인과 다음에 할 일>`을 한 줄 적는다.
   - 바꾼 파일을 `git add`하고 `wip: <작업 ID> 진행 중 (테스트 실패)`로 커밋한다.
   - 마지막 줄을 `status: continue`로 끝낸다. 다음 회차가 이어서 고친다.

## 4. 멈추는 경우 (blocked)
다음 경우에만 `loop/BLOCKED.md`에 작업 ID, 이유, 사람이 정해야 할 것을 쓰고 `status: blocked`로 끝낸다. 이때는 커밋하지 않는다.
- **임상 값**이 필요한데 문서에 없다 (약 용량, 처방, 시각, 활력징후, 정답 기준 등).
- **키·비밀번호**가 필요하다 (키 파일을 열어야만 진행 가능한 경우 포함).
- **문서 범위를 벗어나는 변경**이 필요하다 (문서에 없는 기능, 결정과 다른 동작, `pom.xml`에 새 의존성).

이 외의 어려움(설계 선택, 문서에 적힌 범위 안의 세부 구현)은 문서 범위 안에서 합리적으로 정하고, 정한 내용을 `progress.md`에 적은 뒤 계속한다.

## 5. 완료하면
1. `loop/TASKS.md`에서 해당 작업을 `- [x]`로 바꾸고 날짜(YYYY-MM-DD)를 붙인다.
2. `progress.md`의 변경 기록 표 맨 위에 한 줄을 추가한다 (날짜, 작업 ID와 한 일, 확인 범위).
3. **화면 작업이면** 같은 줄 또는 바로 다음 줄에 `직접 확인할 것: <사람이 화면에서 눈으로 확인할 내용>`을 적는다.
4. 바꾼 파일을 경로를 지정해 `git add`하고 `feat: <작업 ID> <한 일>`로 커밋한다 (한국어로 짧게).
5. **push는 하지 않는다.**

## 6. 금지
- `docs/` 아래 파일 수정 금지. 예외는 저장소 루트의 `progress.md`뿐이다.
- 키 파일(`config/ai.properties`, `config/db.properties`)을 열거나 출력하지 않는다. 코드가 실행 중에 읽는 것은 괜찮다.
- `src/main/resources/cases/allowed-drugs.json`의 약물 값을 채우지 않는다 (D26, 팀이 직접 채움).
- `git push`, 브랜치 변경, `git reset`, `git checkout -- <파일>`로 변경 버리기, 이력 수정을 하지 않는다.
- R1·R2·R5·R7 점검과 점수 가중치는 이번 범위가 아니다.

## 7. 마지막 출력
응답의 **마지막 줄**은 다음 셋 중 정확히 한 줄이다.

```text
status: continue
status: done
status: blocked
```

- `continue`: 이번 작업을 완료해 커밋했고 남은 작업이 있다. 또는 테스트 실패로 wip 커밋을 남겼다.
- `done`: 이번 작업까지 완료해서 체크되지 않은 작업이 없다.
- `blocked`: 4번에 해당해 `loop/BLOCKED.md`를 썼다.
