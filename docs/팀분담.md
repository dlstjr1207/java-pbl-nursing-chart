# 팀 분담

담당자 이름은 팀에서 배정한다. 작업 상태는 [tasks.md](tasks.md)에서 관리하고 이 문서에는 역할과 인계 기준만 둔다.

| 역할 | 담당 | 책임 | 다음 역할에 전달할 것 |
|---|---|---|---|
| A · 환자 데이터·근거 | 미정 | PC-01의 환자 정보·처방·시각·정답 키·모범 기록, 출처 확인 | 일관된 케이스 데이터와 검증 상태 |
| B · 기획·시나리오 | 미정 | 범위·기능 ID·점검 기준·사용자 흐름, 수업 요구사항 확인 | 구현할 동작과 기대 결과 |
| C · 디자인 | 미정 | MVP 화면, 입력·결과 흐름, 공통 스타일, 환자 데이터 반영 | Figma 노드 링크와 확정 시안 |
| D · 구현·검증 | 미정 | 개발 환경·빌드·저장·계정·점검·화면 연결, 사용자 테스트·보고 | 실행 가능한 프로그램과 검증 기록 |

## 이번 단계의 산출물

| 목표 | 관련 작업 | 담당 |
|---|---|---|
| PC-01의 C-01~C-10 정리 | D-01, D-05, D-13 | A, B |
| 점검 적용 조건·모범답안 일치 | D-05, D-06, D-15 | A, B |
| 입력·결과·로그인 화면과 최종 스타일 | D-08, D-09, D-17, D-18 | B, C |
| 로컬 계정 정책과 개발 환경 | D-14, T-00, T-14, T-15 | B, D |
| 제출물·AI 규정·예산·사용자 테스트 | D-11, D-12 | B, D |

기반 코드와 테스트 준비는 설계와 병행한다. 화면 연결과 케이스 채점은 확정된 명세·데이터를 사용한다. 담당자는 작업 결과와 남은 문제를 진행 현황에 기록한다.

## 일정

11/22까지 명세·데이터·디자인을 정리하고, 12/6까지 실습 한 회차를 연결하는 것이 목표다. 12/7~12/14에는 사용자 테스트와 보고서를 진행한다. 수업의 제출일과 제출물은 별도 확인이 필요하다.

일정 변경이나 기능 축소가 필요하면 팀이 범위를 다시 결정하고 결정기록에 남긴다. 담당자가 임의로 다른 문서의 기능을 제외하지 않는다.
