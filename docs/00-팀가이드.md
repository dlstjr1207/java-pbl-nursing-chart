# 팀 가이드 — 지금 어디까지 왔고, 무엇을 해야 하나

> 이 문서 하나만 읽으면 된다. 마지막 정리: 2026-11-16. 상태가 바뀌면 [progress.md](../progress.md)를 고친다.

## 1. 우리가 만드는 것

**간호 차팅 연습 프로그램** (JAVA PBL, Java Swing). 가상 정신과 환자의 정보와 면담 대화록을 읽고 SOAPIE로 차팅하면, 규칙 기반 점검과 AI 해설로 피드백을 받는다. 대상은 간호학부 3·4학년과 1년차 간호사다. **마감은 2026-12-14**이다.

## 2. 우리가 일하는 방식

```
① 문서 완성 (팀)  ─┐
                   ├─→  ③ Claude로 구현 (맥미니)  ─→  ④ 베타 테스트·보고
② 디자인 완성 (팀) ─┘
```

- **① 문서와 ② 디자인은 팀이 직접 완성한다.** Claude는 문서가 명확해야 잘 만든다. 문서가 모호하면 엉뚱한 것이 나온다.
- **③ 구현은 ①②가 끝난 뒤에 시작한다.** 지금은 구현하지 않는다. 랄프 루프(Claude를 반복 실행하는 방식)도 아직 돌리지 않는다.
- **간호 전문가의 검수는 없다.** 그래서 임상 내용은 **근거를 달아서** 쓴다([근거표](근거표.md)). 이것이 이 프로젝트의 핵심 규칙이다.

## 7. 전문가 없이 임상 내용을 쓰는 방법

1. 임상 주장(약, 용량, 수치, 간호 중재, 관찰 항목)은 **근거표의 출처가 있는 것만** 확정한다.
2. 출처는 **등급**이 있다. 학생 과제·블로그(C)만으로는 확정하지 않는다. 교재·논문·공공기관 자료(A/B)를 찾는다.
3. 링크를 열어 **원문을 읽는다.** 검색 요약만 보고 쓰지 않는다. (근거표의 현재 항목들도 원문 확인 전이다.)
4. 못 찾으면 `[검증필요]`로 둔다. 그리고 결과물에 "교육용 예시 · 임상 검수 전"이라고 밝힌다.
5. 대화·관찰은 **판단 없이** 쓴다. "불안해 보임"이 아니라 "손을 계속 움직이며 주위를 두리번거림".
6. 베타 테스트에서 간호학생이 "내용이 현실적이었나"를 평가한다. 틀린 곳은 거기서 잡는다.

## 8. GitHub 사용법 (처음 쓰는 사람용)

**가장 쉬운 방법: GitHub 웹에서 바로 고치기**
1. 저장소에서 고칠 파일을 연다. 오른쪽 위 **연필 아이콘(Edit)** 을 누른다.
2. 수정한다.
3. 오른쪽 위 **Commit changes**를 누르고, 메시지를 적는다. (예: `근거표: G-03 간호기록 지침 추가`) 그리고 확인한다.

**충돌을 피하는 규칙**
- **같은 파일을 두 사람이 동시에 고치지 않는다.** 위 문서 지도의 담당자가 그 파일을 고친다. 다른 사람은 담당자에게 말하거나, 파일 끝에 "의견"으로 적는다.
- `근거표.md`와 `progress.md`는 여러 명이 고친다. **고치기 직전에 새로 고침(F5)** 해서 최신을 연다.
- 코드나 `pom.xml`은 구현 단계 전까지 고치지 않는다.

**로컬에서 받아 쓰는 경우**
```bash
git clone https://github.com/dlstjr1207/java-pbl-nursing-chart.git
git pull
```
(고치기 전에 항상 `git pull`)
