# 팀 가이드

가상 환자의 정보를 바탕으로 관찰 기록·투약 기록·SBAR를 작성하는 실습 프로그램이다. 첫 버전은 PC-01 한 명을 대상으로 한다.

## 읽는 순서

1. [기획안](기획안.md)에서 기능 범위와 점검 기준을 확인한다.
2. [시나리오](시나리오.md)와 [화면명세](화면명세.md)에서 실습 흐름을 확인한다.
3. [작업 목록](tasks.md)과 [팀 분담](팀분담.md)에서 맡을 작업을 정한다.

진행 상황은 [progress.md](../progress.md), 범위 변경은 [결정기록](결정기록.md)에 기록한다. 같은 상태표를 여러 문서에 복사하지 않는다.

## 현재 우선순위

| 작업 | 완료 기준 |
|---|---|
| PC-01 기준 데이터 | 환자 정보·처방·시각·활력징후가 화면과 정답 기준에서 일치 |
| 실습 화면 | 관찰·투약·SBAR 입력과 제출 후 결과 흐름 확정 |
| 개발 환경 | Maven 빌드 및 테스트 실행 확인 |

기반 코드와 테스트 준비는 화면 설계와 병행할 수 있다. 화면 구현은 해당 화면 명세가 정해진 뒤 진행하며, 미확정 환자 수치로 정답을 확정하지 않는다.

## 문서 수정

- 기능과 점검 기준의 기준 문서는 기획안이다. 화면명세와 시나리오는 이를 구체화한다.
- 환자 값은 환자케이스에서 관리한다. Figma의 예시 숫자를 여러 문서에 따로 복사하지 않는다.
- 임상 출처는 근거표의 확인 상태를 함께 본다. 출처가 등록되었다는 것만으로 검증 완료를 뜻하지 않는다.
- `[확인필요]`는 디자인·데이터 대조가 필요한 항목, `[검증필요]`는 근거 확인이 필요한 항목이다.
- 구현 범위 밖의 예전 케이스는 [보관 문서](archive/환자케이스-초안.md)에 있다.

## 협업

수정 전 최신 내용을 확인하고, 커밋 메시지에는 변경한 내용과 이유를 짧게 적는다. 같은 파일을 함께 수정할 때는 담당자끼리 작업 범위를 나눈다. 범위나 정답 기준이 바뀌면 관련 명세와 시나리오도 함께 갱신한다.

실제 환자 정보와 인증 정보는 저장소에 포함하지 않는다. 외부 자료는 출처를 표시하고, 원문과 이미지의 이용 조건을 확인한다. 수업 제출물과 AI 도구 사용 규정은 팀이 확인한다.
