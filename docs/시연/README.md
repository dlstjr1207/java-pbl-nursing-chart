# demo01 시연 실습 5회

- 일시: 2026-11-23, main(0114b18, #11 병합 후) 기준 빌드
- 실행: 실제 메인 창(`Main.createFrame`)을 띄우고 `UiWalkthrough`의 `demo5` 모드로 입력칸에 글을 넣고 버튼을 눌러 제출. 저장은 MySQL, AI 해설·AI 케이스 생성 켬
- 계정: [docs/시연계정.md](../시연계정.md)
- 입력 문장은 학생이 쓴 것처럼 회마다 다르게 썼고, 모범 기록 문장을 복사하지 않았다
- 채점 규칙·배점은 바꾸지 않았다

|---|---|---|---|---|---|
| ① | 김하늘 (PC-01) | 없음 (모범에 가까운 기록) | **100** | R7 25 · R2 20 · R8 20 · R6 15 · R1 10 · R4 10 | 누락·불일치 없음 |
| ② | 김하늘 (PC-01) | 투약 용량 0.5mg | **95** | R7 **20**/25, 나머지 만점 | 불일치: 투약 용량 입력 '0.5', 기준 '1' (R7) |
| ③ | 김하늘 (PC-01) | 발언을 따옴표 없이 바꿔 씀 + '협조적' | **90** | R1 **0**/10, 나머지 만점 | 누락: 환자 발언은 따옴표로 그대로 인용 (R1) · 피드백: '협조적'은 판단 표현 (R1, 배점 없음) |

①~④의 의도한 실수는 모두 예상한 규칙에서 잡혔다. 5회 모두 AI 해설을 받았다(SUCCESS). 결과 화면 상단에는 매번 환자 이름과 케이스 ID가 보였다.

## 확인이 필요한 점 (채점 규칙은 바꾸지 않음)

1. **⑤의 R2 '투약' 누락은 의도한 실수가 아니다.** AI가 만든 처방의 용량이 `1.0`으로 저장되어 있고, 입력 도구가 처방 값을 그대로 이어 "Lorazepam 1.0mg PO"라고 썼다. 정답 키의 투약 동의어는 `1mg|1 mg`라서 `1.0mg`을 찾지 못했다. 투약 기록의 R7은 `1.0`을 받아들였다(용량 키 `1|1.0`). 학생이 처방 표시대로 "1.0mg"이라고 쓰면 같은 감점이 생길 수 있다.
2. ⑤ 관찰 서술 "간호사실 앞 쪽에서 서성 모습이 보임"은 입력 도구가 정답 키 단어를 이어 붙여 생긴 어색한 문장이다(학생 문장답지 않음).
3. ⑤는 '구강 확인'을 체크하지 않았는데 R6(투약 기록 완결성)은 만점이었다. 현재 R6은 구강 확인을 점검 항목에 넣지 않는다.
4. AI 해설의 예시 문장이 케이스에 없는 환자 발언을 지어낸 경우가 있다(③ 예시: "너무 불안하고 마음이 안 잡혀요"). 점수에는 반영되지 않지만 시연 때 설명이 필요하다.
5. 결과 문구의 조사 어색함: "재평가을(를)", "경로이(가)" 등.

## 추천 시연 순서

1. ① 100점: 결과 화면 구성(총점 → 항목별 막대 → 고칠 점 없음 → 모범 기록 공개)
2. ③ 판단 표현: 따옴표 인용 누락(R1 0점)과 '협조적' 피드백(배점 없음)의 차이
3. ② 용량 0.5mg: 투약 값 불일치가 주황색 '불일치'로 보이는 모습
4. ⑤ AI 환자: AI 생성 케이스(ID·임상 검수 전 표시)와 AI 해설. 위 1번을 고친 뒤 다시 찍는 것을 권장
5. (시간 있으면) ④ 재평가 누락과 SBAR R 피드백
