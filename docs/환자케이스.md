# 환자 케이스

첫 버전의 기본 실습 대상은 PC-01 한 명이다. 이 문서는 화면과 정답 데이터의 기준을 관리한다.

**PC-01 상태: 팀 확정 초안 (용량 원문 확인, 적응증 검토 대기)** — 2026-11-23. 처방 용량은 허가 용법 원문(E-20·E-21·E-28·E-29)으로 확인했고, 진단과 적응증의 차이(아래 C-03·C-05)는 `[검증필요]`로 남긴다. 임상 전문가 검수 전의 교육용 예시다.

**PC-01의 역할 (D28, D24 수정):** AI 키가 없는 PC의 기본 케이스, 테스트용 고정 케이스, AI 생성 케이스의 견본이다. AI 생성 대신 Figma 값과 허가 용법 원문 확인으로 팀이 직접 확정했다. 파일은 `src/main/resources/cases/PC-01.json`이다.

**DEMO 케이스 (D25):** PC-01 확정 전 화면 개발용 `cases/demo.json`. PC-01이 있으면 기본 케이스는 PC-01이다. DEMO는 채점 정답·만점 테스트에 쓰지 않는다.

**허용 약물 (D26, D29):** `cases/allowed-drugs.json`. AI 생성 케이스는 이 목록 안의 약과 용량 범위만 쓴다(아래 'AI 생성 케이스의 기준').

## AI 생성 케이스의 기준

AI가 케이스를 만들 때 따르는 틀이다. 근거가 확인되지 않은 항목은 `[검증필요]`다.

| 사건 유형(후보) | 학생이 기록할 핵심 | 관련 점검 | 첫 도입 |
|---|---|---|---|
| 불안 증가 → PRN 투약 → 재평가 | 행동·발언 인용, PRN 사유·용량, 재평가 | R1, R2, R4, R6, R7 | ✓ (PC-01과 같은 유형) |
| 복약 거부 | 거부 사유 인용, 결과·사유, 보고 | R1, R6 | 후보 |
| 구강 은닉 의심 | 관찰 사실, 확인 절차, 보고 | R1, R2 | 후보 `[검증필요]` E-24 |
| 초조·공격적 언행 | 행동 기술, 중재, 안전 조치 | R1, R2 | 후보 |
| 약물 부작용(급성 근긴장이상 등) | 증상 관찰, 활력징후, 보고·처치 | R2, R7 | 후보 `[검증필요]` E-14·E-23 |
| 자해 위험 발언 | 위험사정 | R3 | **후속**(R3이 후속 범위) |

- **허용 약물·용량 범위(D29):** Aripiprazole PO 1일 10~30mg(E-20), Olanzapine PO 1일 5~20mg(E-28), 탄산리튬 PO 1일 600~1800mg 3회 분할(E-21), Lorazepam PO 1일 1~4mg, PRN 1회 0.5 또는 1mg `[검증필요]`(E-29). 그 외 약은 생성하지 않는다.
- **정답 키 필수:** 생성 케이스에도 PC-01과 같은 형식의 정답 키가 있어야 하고, 정답 키의 약·용량은 그 케이스의 처방과 같아야 한다.
- **유형별 필수 사실 항목:** 불안·PRN 유형은 사건 시각·장소·행동·발언·간호·투약·재평가가 모두 있어야 한다. 이 항목이 R2·R8의 기준이 된다.
- 생성된 케이스는 임상 검수를 거치지 않는다. 화면에 `AI 생성 · 임상 검수 전`을 표시한다.

### R1 발언·관찰 구분 (관찰 기록 서술)

- 환자 발언은 따옴표(" ", “ ”, ' ', ‘ ’)로 인용한다. 인용이 없으면 지적한다.
- 판단 표현 목록 `협조적`, `비협조적`, `이상한`, `정상적`, `잘 지냄`, `문제없음`이 있으면 "관찰한 행동으로 바꿔 쓰세요"로 피드백한다. 근거가 E-04(등급 C)뿐이라 `[검증필요]` 교육용 예시이며 배점 없이 피드백만 한다(시나리오 V1).

### R4 재평가 연결

관찰 기록(서술·처치) 또는 투약 기록(재평가 계획)에 재평가 계획이 있어야 한다.

`[검증필요]` R의 "16:00 관찰" 시각은 모범 기록을 만들 때 정한 예시 시각이다(케이스 데이터나 근거표에서 온 값이 아님). 채점(R9)은 R 행의 시각·중재가 있는지만 보고 이 시각과 같은지는 보지 않는다.

## 데이터 변환

| 문서 자료 | JSON 항목 |
|---|---|
| 케이스 정보 | id, title, difficulty, objectives, reviewStatus |
| 환자·알레르기·위험 지표 | patient, adr, riskTier |
| 처방·변경 이력·농도 | orders, regimenHistory, lithiumLevel |
| 측정·기존 기록 | vitals, observationLog, safetyRounds |
| 제출 전 자료 | briefing, sbarReference |
| 제출 후 자료 | answerKey, modelAnswer |

정규·PRN 처방과 측정 시각을 구별할 식별자를 둔다. 미확정 숫자를 임시 정답으로 채우지 않는다. DRAFT 데이터는 검토용으로 표시하고, 채점에 쓰이는 필수값이 미확정이면 해당 시나리오의 채점 검증을 보류한다.

확정 시에는 Figma·케이스·정답 키·모범 기록·시나리오를 같은 값으로 대조하고, [근거표](근거표.md)의 출처와 확인 상태를 연결한다.
